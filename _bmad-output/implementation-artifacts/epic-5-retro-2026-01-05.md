## Challenges & Growth Areas 📈

### 1. Placeholder Images Still Used
All projects currently use the same SVG placeholder image. While functional, real project screenshots would significantly improve the portfolio's credibility and visual appeal.

**Evidence from Story 5.3:**
> "All projects use `placeholder.svg`"
> "Real screenshots need to be created/collected"

**Lesson Learned:** Consider creating a backlog item for replacing placeholder images with actual project screenshots before deployment.

### 2. Project Data Hardcoded in Component
Project data is currently hardcoded in the ProjectsSection component. While acceptable for MVP, this makes content updates require code changes.

**Evidence from Story 5.3:**
> "Project data hardcoded in `ProjectsSection.razor`"
> "ProjectData class defined inline in component"

**Lesson Learned:** For future enhancements, consider extracting project data to a separate model, JSON file, or data service for easier content management.

### 3. Technology Tags Don't Reuse SkillBadge
Technology tags in ProjectCard use similar styling to SkillBadge but don't actually reuse the component. This creates code duplication.

**Evidence from Story 5.2:**
> "Technology tags styled similarly to SkillBadge"
> "Tags: `rounded-full px-2 py-1 text-xs font-medium`"

**Lesson Learned:** Consider refactoring to reuse SkillBadge component for technology tags, or create a more generic Badge component that both can use.

### 4. No Visual Differentiation for Project Types
All project cards appear identical. While the content varies, there's no visual indication of project category (frontend, backend, AI/ML).

**Evidence from Story 5.3:**
> "Projects showcase variety in technologies" but visually identical

**Lesson Learned:** Consider adding visual indicators (badges, icons, or subtle color variations) if project categorization is important.

2. **Responsive Grid Patterns**
   - Mobile-first approach: `grid-cols-1 md:grid-cols-2 lg:grid-cols-3`

   - `<article>` for card components
   - Proper heading hierarchy (`<h2>` section, `<h3>` card titles)
   - Descriptive alt text for images
   - External link attributes for security

4. **Hover Effects Pattern**
