## Challenges & Growth Areas 📈

### 1. Tailwind v4 Migration Learning Curve
Tailwind v4 has significant changes from v3 (CSS-first config, `@import "tailwindcss"` syntax). Initial research was needed to understand the new patterns.

**Lesson Learned:** When using newer framework versions, allocate time for documentation review and syntax changes.

### 2. .NET 10 Preview SDK in CI
The GitHub Actions workflow initially didn't account for .NET 10 being a preview SDK, requiring the `dotnet-quality: "preview"` flag.

**Evidence from Story 1.5:**
> "[MEDIUM] .NET 10 preview flag: Added `dotnet-quality: "preview"` to setup-dotnet action"

**Lesson Learned:** Check SDK availability in CI environments for preview versions.

### 3. Dark Mode Class Confusion
Initial implementation confused Tailwind's `dark:` prefix (OS-based) with class-based dark mode, leading to non-functional classes on body element.

**Evidence from Story 1.2:**
> "[MEDIUM] dark:/light: prefix misuse - Removed non-functional classes from body"

**Lesson Learned:** Tailwind's `dark:` variant with `darkMode: 'class'` responds to a `.dark` class on ancestors, not the element itself.

### 4. Placeholder Assets
OG image and some SEO assets were left as placeholders with README documentation rather than actual assets.

**Lesson Learned:** Design assets should be created alongside or before implementation stories that reference them.

### 5. Verification Tasks Deferred
Several verification tasks (browser testing, Lighthouse audits, live deployment) require manual testing or a live URL, which were deferred.

**Evidence from Story 1.4 & 1.5:**
> Tasks 5.1-5.4 marked incomplete - requires push to repository

## Key Insights & Learnings 💡

### Technical Insights

1. **Blazor WASM Loading Strategy Works**
   - Static HTML shell renders immediately (<500ms)
   - CSS transitions provide smooth handoff to Blazor
   - Theme resolution before body render eliminates FOUC

2. **Architecture-First Pays Off**
   - Having the architecture document before coding prevented 90% of structural debates
   - Folder structure decisions made implementation straightforward
   - Naming conventions prevented inconsistencies

3. **MSBuild Tailwind Integration**
   - Tailwind compiles automatically on `dotnet build`
   - Debug/Release conditional minification works well
   - No separate build step needed during development

### Process Insights

   - Every story had issues found in review
   - High severity issues caught before merge
   - Review process is not optional for quality

2. **Story Documentation Value**

   - File lists tracked changes accurately
